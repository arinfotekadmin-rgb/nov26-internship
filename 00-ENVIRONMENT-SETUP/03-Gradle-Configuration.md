# 03. Gradle Configuration for Android Projects

## Learning objectives

- Understand the role of Gradle.
- Identify the important Gradle files.
- Understand plugins, dependencies and repositories.
- Run a Gradle sync and build.
- Diagnose common build failures.

## 1. What is Gradle?

Gradle is the build automation system used by Android projects. It resolves dependencies, compiles source code, runs tests and packages application outputs.

Android projects commonly use Kotlin DSL files ending in `.gradle.kts`.

## 2. Important project files

| File | Purpose |
|---|---|
| `settings.gradle.kts` | Project name, included modules and plugin management |
| Root `build.gradle.kts` | Project-level plugin declarations and shared configuration |
| `app/build.gradle.kts` | Android app module configuration and dependencies |
| `gradle/libs.versions.toml` | Optional version catalogue for dependency versions |
| `gradle/wrapper/gradle-wrapper.properties` | Gradle Wrapper distribution configuration |
| `gradlew.bat` | Windows Gradle Wrapper launcher |

The exact files generated by Android Studio can differ by template and release.

## 3. Understand the app module

A simplified example:

```kotlin
plugins {
    alias(libs.plugins.android.application)
    alias(libs.plugins.kotlin.android)
}

android {
    namespace = "in.co.arinfotek.app"
    compileSdk = 35

    defaultConfig {
        applicationId = "in.co.arinfotek.app"
        minSdk = 26
        targetSdk = 35
        versionCode = 1
        versionName = "1.0"
    }
}
```

This is an illustrative structure, not a version recommendation. Your generated project may use newer plugin conventions or a different Compose compiler configuration. Keep the generated versions and syntax compatible.

Important settings:

- `namespace`: namespace used for generated Android classes and resources.
- `applicationId`: unique identifier used to identify the installed app.
- `compileSdk`: API platform used during compilation.
- `minSdk`: minimum supported Android API level.
- `targetSdk`: target behaviour and compatibility level.
- `versionCode`: integer version used by Android distribution.
- `versionName`: human-readable version label.

## 4. Plugins and dependencies

A plugin adds build capabilities. A dependency adds a library your source code can use.

For example, an Android application plugin configures the Android application build. A Compose UI library provides Compose UI APIs.

Do not add dependencies simply because a tutorial lists them. Add only what your project needs, and check official compatibility information.

## 5. Repositories

Repositories are locations from which Gradle downloads plugins and libraries. Modern Android projects commonly use `google()` and `mavenCentral()`.

Do not add unknown repositories or download executable libraries from untrusted locations.

## 6. Gradle Wrapper

The Gradle Wrapper allows a project to use a declared Gradle version without requiring a separately installed Gradle distribution.

On Windows, open the project terminal and run:

```powershell
.\gradlew.bat --version
```

To build the debug variant:

```powershell
.\gradlew.bat assembleDebug
```

The debug APK is commonly created under:

```text
app\build\outputs\apk\debug\app-debug.apk
```

The exact output path can vary by build configuration.

## 7. Gradle sync

Gradle sync reads the build configuration and resolves the required plugins and dependencies.

In Android Studio:
1. Open the project.
2. Wait for the initial sync.
3. If needed, select Sync Project with Gradle Files.
4. Read the Build output if sync fails.

## 8. Common errors

### Gradle download timeout
Check internet access, proxy configuration and firewall rules.

### Plugin and Gradle version incompatibility
Use the compatibility guidance for the Android Gradle Plugin and Gradle versions. Avoid changing several version numbers at once.

### Dependency not found
Check the dependency coordinates and repository configuration.

### Build cache issue
First retry the build and inspect the actual error. Use cache deletion only when there is evidence of a corrupted cache. Avoid deleting the entire `.gradle` directory as a routine fix.
